# 供应链脆弱性分析方法

> 配套工具：`tools/run_risk.py` + `tools/supplier_research/risk.py`
> 数据来源：`data/apple_supply_chain.json`（图谱单一来源，纯标准库、零三方依赖）

## 1. 目标

从**供应链图谱结构**出发，回答一个具体问题：

> **从供应链脆弱性角度，哪条产品线（iPhone / Mac / iPad / Wearable / Spatial / Audio）面临的供应链风险最大？**

方法走「自下而上」路线：先评估**每个零部件**的脆弱性，再聚合到**产品**，最后上卷到**产品线**。
不依赖份额 / 金额等定量权重，只基于图中最稳健、最直觉的结构信号——**一个部件有多少供应商**。

## 2. 模型

### 2.1 零部件脆弱性

对每个组件 `c`，设其供应商数量为 `n_c`（来自 `SUPPLIED_BY` 边）：

```
V_comp(c) = 1 / n_c
```

- `n_c = 1` → `V = 1.0`：**单点依赖**。该组件只有唯一供应商，一旦断供即停产，最脆弱。
- `n_c = 0` → 视作单点（缺供应数据），`V = 1.0`，并打 `missing_data` 标记。
- `n_c` 越大 → 越可替代，`V` 越小（双源 0.5、三源 0.33、六源 0.17 …）。

直觉：**供应商越少，潜在越脆弱（单点依赖风险）**。

### 2.2 产品脆弱性

对产品 `p`，聚合其全部零部件的脆弱性 `vs = [V_comp(c) for c in p 的组件]`：

```
product_vuln = 0.5 × mean(vs)      # 整体暴露：零部件脆弱性均值
            + 0.3 × max(vs)        # 最弱环节：单个最脆弱部件的脆弱性
            + 0.2 × sp_rate        # 单点占比：单点部件数 / 部件总数
```

三项均落在 `[0,1]`，加权求和 → 产品脆弱性亦在 `[0,1]`。

- **mean(vs)** 衡量整体暴露：产品平均有多依赖少数供应商。
- **max(vs)**（最弱环节）遵循「木桶短板」逻辑：一个致命单点就能拖垮整条供应链。
- **sp_rate** 衡量单点密度：单点部件占比越高，整体越脆。

权重 `(0.5, 0.3, 0.2)` 为可调常量（`risk.py` 顶部 `W_MEAN / W_WEAK / W_SP`），可按业务偏好调整。

### 2.3 产品线脆弱性

按 `product_line` 分组，取组内产品脆弱性的**均值**作为该线整体脆弱性，并汇总：
`mean_weakest`（最弱环节均值）、`single_point_total`（单点部件总数）、`single_point_rate`（单点占比），
同时记录组内**最脆弱产品**（`worst_product`）以便定位。

## 3. 风险等级

脆弱性分数按阈值分档（常量 `HIGH_THRESHOLD=0.6` / `MEDIUM_THRESHOLD=0.3`）：

| 分数 | 等级 |
|------|------|
| ≥ 0.6 | 高 |
| 0.3 – 0.6 | 中 |
| < 0.3 | 低 |

## 4. 地理分散度（参考信号，不计入主分数）

对每个组件额外输出 `distinct_countries`（供应商覆盖的不同国家数）。
**同国多源 ≠ 真冗余**：例如某双源组件两家供应商都在同一国家，其抗地缘 / 灾害冲击能力远低于
分处两国的双源。该字段用于人工识别「伪冗余」陷阱，是图结构独有的洞察，但暂不计入主分数，
留作后续扩展。

## 5. 如何运行

```bash
python3 tools/run_risk.py                 # 全量 → tools/output/{supply_chain_risk.md,json}
python3 tools/run_risk.py --top 5         # 仅打印 Top5 最脆弱产品线/产品/零部件
python3 tools/run_risk.py --md out.md --json out.json
```

产物：
- `tools/output/supply_chain_risk.md` —— 人读报告（产品线排名 / 最脆弱零部件 / 最脆弱产品三张表）。
- `tools/output/supply_chain_risk.json` —— 机器可读结果（含 meta / product_lines / products / components 三级）。

## 6. 局限性

- 仅以「供应商数量」为脆弱性主信号，未纳入份额、金额、产能、替代弹性、地缘与制裁风险等定量权重。
- 关系边为二元（是否供应），不含 `share` 之外的真实依赖强度；`tier` 层级为定性标注。
- 当前图谱供应商高度分散（多数组件 2–6 源），故产品线间差异主要来自少数单点 / 双源部件，
  排名区分度有限，属正常数据特征。
- 数据由 AI 联网检索公开资料整合，可能错漏或滞后，**不构成任何采购或投资建议**。

## 7. 后续可扩展方向

- 把地理分散度纳入主分数（伪冗余惩罚项）。
- 引入 `share` 权重：用份额加权计算「有效供应商数」。
- 在图谱上做**断供情景压力测试**：移除某供应商，计算受影响产品 / 产品线（爆破半径）。
- 社群检测识别核心枢纽，构建**风险传导**模型（单点断供的波及范围）。
